# Core - Архитектура вычислительного ядра

Асинхронный Rust-сервер выступает в роли кроссмодельного вычислительного хаба: принимает сырые координаты CV-моделей и приводит их к единому скелету, фильтрует шум и пересчитывает точки в локальные кватернионы 56 костей стандарта `SkeletonProfileHumanoid` из **Godot Engine**.

## 1. Архитектурные принципы

- Вычислительный пайплайн не знает какая CV-модель сейчас используется. Данные приводятся к единому формату в `adapters/`.
- Если модель не отслеживает стопы или кисти, то адаптер выставит `None`, а `solver` безопасно пропускает расчёт этих костей, оставляя их в предыдущих значениях.
- Внутри ядра все вычисления ведутся строго в **glTF**: `+X` - вправо, `+Y` - вверх, `-Z` - вперёд.
- Ядро хранит состояние всех 56 костей.
- Пакеты тела/рук/лица обрабатываются и отсылаются отдельно в виде единого скелета на 56 костей с данными недостающих костей, взятых из истории.

## 2. Асинхронные каналы и потоки данных

1. Слой приёма (`ws_server` -> `solver`)

- Сетевой слой декодирует бинарный `CaptureEventPacket` и транслирует события в единый канал `tokio::sync::mpsc::channel(16)`.
- `tokio::sync::mpsc::channel(16)` гарантирует, что управляющий пакет `Handshake` не будет перезаписан следующим кадром, а модуль истории получит необходимый объём кадров для точного расчёта.

> В перспективе добавить `udp_server` -> `solver` для нативных приложений.

2. Слой отправки

- Канал передачи `tokio::sync::watch::channel`.
- Хранит только самый свежий просчитанный кадр. При сетевых задержках устаревшие кадры автоматически отбрасываются.
- `udp_client` переиспользует выделенный буфер между отправками, исключая аллокации памяти.

## 3. Вычислительный конвейер

Состоит из 4 этапов:

1. Adapters - сырой массив модели -> `UnifiedBodyPose` в координатах **glTF**.
2. Tracking - история данных, вычисление пути при потере точек, 1€ фильтр.
3. Calibration - калибровка, оценка и расчёт смещения таза.
4. Solver - воссоздание готовой модели на 56 костей.
